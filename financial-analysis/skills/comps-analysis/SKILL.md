# 比較会社分析（Comparable Company Analysis）

## ⚠️ 重要：データソースの優先順位（最初に確認すること）

**常に以下のデータソース優先順位に従うこと：**

1. **最優先：MCPデータソースを確認する** — S&P Kensho MCP、FactSet MCP、または Daloopa MCP が利用可能な場合、財務・取引情報はそれらを専用で使用する
2. **上記MCPデータソースが利用可能な場合はウェブ検索を使用しない**
3. **MCPが利用不可の場合のみ：** Bloomberg Terminal、SEC EDGARのfilings、またはその他の機関投資家向けソースを使用する
4. **ウェブ検索を一次データソースとして使用しない** — 機関投資家水準の分析に必要な精度・監査証跡・信頼性が欠如している

**理由：** MCPソースは適切な引用が付いた検証済みの機関投資家水準データを提供する。ウェブ検索の結果は陳腐化・不正確・信頼性に欠けるリスクがある。

---

## 概要
このスキルは、オペレーティング指標・バリュエーション・マルチプル・統計的ベンチマーキングを組み合わせた機関投資家水準の比較会社分析を構築する。アウトプットはピア比較を通じた投資判断を可能にする構造化されたExcelシートである。

**参考資料とコンテキストの活用：**

比較会社分析のサンプルが `examples/comps_example.xlsx` に収録されている。このスキルディレクトリ内のサンプルファイルを使用する際は、以下の観点で活用すること：

**サンプルを参考にすべき点：**
- 構造の階層（セクションの流れ）の理解
- 求められる厳密さの水準（統計的深度、文書化基準）の把握
- 原則の習得（明確なヘッダー、透明なフォーミュラ、監査証跡）

**サンプルをそのまま使うべきでない点：**
- フォーマットや指標の完全複製
- コンテキストを考慮せずにレイアウトをコピーすること
- 対象者に関係なく同じビジュアルスタイルを適用すること

**常に最初に自問すること：**
1. **「希望のフォーマットがあるか、それともテンプレートスタイルを適応させるか？」**
2. **「対象者は誰か？」**（投資委員会、取締役会プレゼン、クイックリファレンス、詳細メモ）
3. **「核心的な問いは何か？」**（バリュエーション、成長分析、競合ポジショニング、効率性）
4. **「コンテキストは何か？」**（M&A評価、投資判断、セクターベンチマーキング、パフォーマンスレビュー）

**具体的な状況に応じて適応させること：**
- **業界コンテキスト**：大型テクノロジー企業と新興SaaSスタートアップでは異なる指標が必要
- **セクター固有のニーズ**：関連指標を早期に追加する（例：テクノロジーにはクラウドARR、エンタープライズ顧客数、開発者エコシステム等）
- **銘柄の知名度**：よく知られた銘柄はバックグラウンド説明を省いてデルタ分析に注力できる
- **意思決定の種類**：M&A評価と継続的なポートフォリオモニタリングでは強調点が異なる

**基本原則：** テンプレートの原則（明確な構造、統計的厳密さ、透明なフォーミュラ）を活用しつつ、コンテキストに応じて実行を変える。目標は「機関投資家らしく見えるテンプレート」ではなく「機関投資家水準の分析」である。

ユーザーが提供したサンプルと明示的な設定は常にデフォルトより優先される。

## コアフィロソフィー
**「まず正しい構造を作り、それからデータにストーリーを語らせる。」**

戦略的に重要な項目を強制的に考えさせるヘッダーから始め、クリーンなデータを入力し、透明なフォーミュラを構築し、統計が自然に浮かび上がるようにする。良いCompsとは、作成者でなくても即座に読み解けるものである。

## ⚠️ 重要：フォーミュラ優先・ステップバイステップ検証

**環境 — Office JS vs Python：**
- **Excel内での実行（Office Add-in / Office JS）：** Office JS を直接使用する（`Excel.run(async (context) => {...})`）。フォーミュラは `range.formulas = [["=E7/C7"]]` で書く（`range.values` は使わない）。Excel がネイティブに計算するため、別途recalcのステップは不要。色・フォントには `range.format.*` を使用する。
- **スタンドアロン .xlsx ファイルの生成：** Python/openpyxl を使用する。`cell.value = "=E7/C7"` （フォーミュラ文字列）と書く。
- どちらの環境でも原則は同じ — APIの書き方を変えるだけ。
- **Office JS のセル結合の落とし穴：** `.merge()` を呼び出してから結合範囲に `.values` をセットしない（`InvalidArgument` が発生する — 結合前の次元のままreportされる）。代わりに、左上のセル単体に値を書いてから、全範囲に対してmergeとformatを適用する：
  ```js
  ws.getRange("A1").values = [["TECHNOLOGY — COMPARABLE COMPANY ANALYSIS"]];
  const hdr = ws.getRange("A1:H1");
  hdr.merge();
  hdr.format.fill.color = "#1F4E79";
  hdr.format.font.color = "#FFFFFF";
  hdr.format.font.bold = true;
  ```

**フォーミュラ、ハードコードしない：**
- すべての派生値（マージン、マルチプル、統計）はインプットセルを参照するExcelフォーミュラでなければならない — 事前計算した数値を貼り付けてはいけない
- Python/openpyxl でシートを構築する場合：`cell.value = "=E7/C7"` （フォーミュラ文字列）と書く。`cell.value = 0.687`（計算済み結果）は不可
- ハードコードして良い値は生のインプットデータのみ（売上高、EBITDA、株価等）— それぞれのセルにはソースを記載したセルコメントを付ける
- 理由：インプットが変更された際にモデルが自動更新されなければならない。ハードコードされたマージンは気づかれにくいバグの温床となる。

**ユーザーとのステップバイステップ検証：**
- 構造設定後 → データ入力前にヘッダーレイアウトをユーザーに確認する
- 生データ入力後 → フォーミュラ構築前にインプットブロックとソース・期間をユーザーに確認する
- オペレーティング指標フォーミュラ構築後 → バリュエーションに進む前に計算されたマージンをユーザーとサニティチェックする
- バリュエーション・マルチプル構築後 → 統計を追加する前にマルチプルが合理的か確認する
- シート全体をエンドツーエンドで構築してから提示しない — 各セクションを確認することで早期にエラーを捕捉する

## Section 1：ドキュメント構造と設定

### ヘッダーブロック（Row 1〜3）
```
Row 1: [分析タイトル] - COMPARABLE COMPANY ANALYSIS
Row 2: [ティッカー付き会社リスト] • [会社1 (TICK1)] • [会社2 (TICK2)] • [会社3 (TICK3)]
Row 3: As of [期間] | All figures in [USD Millions/Billions] except per-share amounts and ratios
```

**重要な理由：** コンテキストを即座に確立する。このファイルを開いた人が、何の分析か・いつ作成されたか・数値の解釈方法を瞬時に把握できる。

### ビジュアル規約（任意 — ユーザーの設定とアップロードされたテンプレートは常に優先）

**重要：以下はあくまでデフォルト案である。常に以下を優先すること：**
1. ユーザーの明示的なフォーマット設定
2. アップロードされたテンプレートファイルのフォーマット
3. 会社・チームのスタイルガイド
4. このデフォルト（他に指針がない場合のみ）

**推奨フォント・タイポグラフィ：**
- **フォントファミリー**：Times New Roman（プロフェッショナルで読みやすく、業界標準）
- **フォントサイズ**：データセル11pt、ヘッダー12pt
- **太字**：セクションヘッダー、会社名、統計ラベル

**デフォルト配色 — プロフェッショナルなブルー/グレーパレット（ミニマルが基本）：**
- **控えめに** — ブルーとグレーのみ使用。グリーン・オレンジ・レッド・複数のアクセントカラーは不可。クリーンなCompsシートは3〜4色のみ使用する。
- **セクションヘッダー**（例："OPERATING STATISTICS & FINANCIAL METRICS"）：
  - ダークブルー背景（`#1F4E79` またはネイビー `#17365D`）
  - ホワイト太字テキスト
  - 全カラムにわたる行全体のシェーディング
- **列ヘッダー**（例："Company"、"Revenue"、"Margin"）：
  - ライトブルー背景（`#D9E1F2` または類似の薄いブルー）
  - ブラック太字テキスト
  - 中央揃え
- **データ行**：
  - 会社データはホワイト背景
  - フォーミュラはブラックテキスト、ハードコードのインプットはブルーテキスト
- **統計行**（Maximum、75th Percentileなど）：
  - ライトグレー背景（`#F2F2F2`）
  - ブラックテキスト、左揃えラベル
- **パレットの全体像**：ダークブルー + ライトブルー + ライトグレー + ホワイト。ユーザーのテンプレートに別の指定がない限り、これ以外は使わない。

**推奨フォーマット規約：**
- **小数点精度**：
  - パーセンテージ：小数点1桁（12.3%）
  - マルチプル：小数点1桁（13.5x）
  - ドル金額：小数点なし、千単位区切り（69,632）
  - マージン（%表示）：小数点1桁（68.7%）
- **罫線**：なし（クリーンでミニマルな外観）
- **揃え**：すべての指標を中央揃えにすることで統一された外観を実現
- **セルサイズ**：すべての列幅を均一に、すべての行高さを統一する（クリーンでプロフェッショナルなグリッドを作る）

**注意：** ユーザーがテンプレートファイルを提供するか異なるフォーマットを指定した場合は、それに従うこと。

## Section 2：オペレーティング指標・財務メトリクス

### コア列（まずここから）
1. **Company** — 統一されたフォーマットで会社名
2. **Revenue** — 規模の指標（コンテキストに応じてLTM、四半期、または年次）
3. **Revenue Growth** — 前年比の増減率
4. **Gross Profit** — 売上高からCOGSを引いた値
5. **Gross Margin** — GP/Revenue（基本的な収益性）
6. **EBITDA** — 利払い・税・減価償却前利益
7. **EBITDA Margin** — EBITDA/Revenue（オペレーティング効率）

### 任意追加（業界・目的に応じて選択）
- **四半期 vs LTM** — 季節性が重要な場合は両方含める
- **Free Cash Flow** — 設備投資集約型またはSaaSビジネスに
- **FCF Margin** — FCF/Revenue（キャッシュ創出効率）
- **Net Income** — 成熟した黒字企業に
- **Operating Income** — D&Aにばらつきがあるビジネスに
- **CapExメトリクス** — 資産集約型産業に
- **Rule of 40** — SaaS専用（成長率% + マージン%）
- **FCF Conversion** — 収益の質分析に（上級）

### フォーミュラ例（Row 7を例として）
```excel
// コア比率 — 常に計算する
Gross Margin (F7): =E7/C7
EBITDA Margin (H7): =G7/C7

// 任意比率 — 関連する場合に含める
FCF Margin: =[FCF]/[Revenue]
Net Margin: =[Net Income]/[Revenue]
Rule of 40: =[Growth %]+[FCF Margin %]
```

**黄金則：** すべての比率は [何か] / [Revenue] または [何か] / [このシートの別の何か] であること。シンプルに保つ。

### 統計ブロック（会社データの後）

**重要：すべての比較可能な指標（比率、マージン、成長率、マルチプル）に統計フォーミュラを追加すること。**

```
[視覚的な区切りのために1行空ける]
- Maximum: =MAX(B7:B9)
- 75th Percentile: =QUARTILE(B7:B9,3)
- Median: =MEDIAN(B7:B9)
- 25th Percentile: =QUARTILE(B7:B9,1)
- Minimum: =MIN(B7:B9)
```

**統計が必要な列（比較可能な指標）：**
- Revenue Growth %、Gross Margin %、EBITDA Margin %、EPS
- EV/Revenue、EV/EBITDA、P/E、Dividend Yield %、Beta

**統計が不要な列（規模の絶対値指標）：**
- Revenue、EBITDA、Net Income（規模によって絶対値が異なる）
- Market Cap、Enterprise Value（会社規模が異なれば比較できない）

**注意：** 会社データと統計行の間に視覚的な区切りとして1行空ける。"SECTOR STATISTICS" や "VALUATION STATISTICS" のヘッダー行は追加しない。

**四分位数が重要な理由：** 平均だけでなく分布を示す。75thパーセンタイルのマルチプルは「プレミアム」企業の取引水準を示す。

## Section 3：バリュエーション・マルチプルと投資指標

### コアバリュエーション列（まずここから）
1. **Company** — オペレーティングセクションと同じ順序
2. **Market Cap** — 現在の市場価値
3. **Enterprise Value** — Market Cap ± Net Debt/Cash
4. **EV/Revenue** — 売上1ドルに対して市場が支払う価格
5. **EV/EBITDA** — 利益1ドルに対して市場が支払う価格
6. **P/E Ratio** — 純利益に対する株価

### 任意バリュエーション指標（コンテキストに応じて選択）
- **FCF Yield** — FCF/Market Cap（キャッシュ重視の分析に）
- **PEG Ratio** — P/E ÷ 成長率（成長企業に）
- **Price/Book** — 市場価値 vs 簿価（資産集約型ビジネスに）
- **ROE/ROA** — リターン指標（収益性比較に）
- **Revenue/EBITDA CAGR** — 過去成長率（トレンド分析に）
- **Asset Turnover** — Revenue/Assets（オペレーション効率に）
- **Debt/Equity** — レバレッジ（資本構成分析に）

**重要原則：** 業界にとって重要な3〜5のコアマルチプルを含める。可能なすべての指標を含めようとしない。

### フォーミュラ例
```excel
// コアマルチプル — 常に含める
EV/Revenue: =[Enterprise Value]/[LTM Revenue]
EV/EBITDA: =[Enterprise Value]/[LTM EBITDA]
P/E Ratio: =[Market Cap]/[Net Income]

// 任意マルチプル — データが利用可能な場合に含める
FCF Yield: =[LTM FCF]/[Market Cap]
PEG Ratio: =[P/E]/[Growth Rate %]
```

### クロスリファレンスの原則
**重要：** バリュエーション・マルチプルはオペレーティング指標セクションを参照しなければならない。同じ生データを2度入力しない。売上高がC7にあれば、EV/Revenueフォーミュラは C7 を参照すること。

### 統計ブロック
オペレーティングセクションと同じ構造：すべての指標に対して Max、75th、Median、25th、Min を追加する。会社データと統計行の間に視覚的な区切りとして1行空ける。"VALUATION STATISTICS" ヘッダー行は追加しない。

## Section 4：注記と方法論の文書化

### 必須コンポーネント

**データソースと品質：**
- データはどこから取得したか？（S&P Kensho MCP、FactSet MCP、Daloopa MCP、Bloomberg、SEC filings）
- 対象期間は？（Q4 2024、監査済み数値）
- どのように検証したか？（10-K/10-Q との照合）
- 注意：精度とトレーサビリティの観点から、利用可能な場合はMCPデータソース（S&P Kensho、FactSet、Daloopa）を優先する

**主要な定義：**
- EBITDAの計算方法（Gross Profit + D&A、または Operating Income + D&A）
- Free Cash Flowの計算式（Operating CF - CapEx）
- 特殊指標の説明（Rule of 40、FCF Conversion）
- 期間の定義（LTM、CAGRの計算期間）

**バリュエーション方法論：**
- Enterprise Valueの計算方法は？（Market Cap + Net Debt）
- 使用した成長率は？（過去CAGR、将来予測）
- 調整はあるか？（一時的項目の除外、正常化マージン）

**分析フレームワーク：**
- 投資テーシスは？（クラウド/SaaSの効率性）
- 最も重要な指標は？（キャッシュ創出、資本効率）
- 読み手への統計の解釈方法は？（四分位数がコンテキストを提供する）

## Section 5：適切な指標の選択（意思決定フレームワーク）

### 「自分が答えようとしている問いは何か？」から始める

**「どの会社が割安か？」**
→ 注目：EV/Revenue、EV/EBITDA、P/E、Market Cap
→ 省略：オペレーションの詳細、成長指標

**「どの会社が最も効率的か？」**
→ 注目：Gross Margin、EBITDA Margin、FCF Margin、Asset Turnover
→ 省略：規模指標、絶対金額

**「どの会社が最も速く成長しているか？」**
→ 注目：Revenue Growth %、EBITDA CAGR、ユーザー/顧客成長
→ 省略：マージン指標、レバレッジ比率

**「最もキャッシュを生む会社はどこか？」**
→ 注目：FCF、FCF Margin、FCF Conversion、CapEx集中度
→ 省略：EBITDA、P/E比率

### 業界別の指標選択

**ソフトウェア/SaaS：**
必須：Revenue Growth、Gross Margin、Rule of 40
任意：ARR、Net Dollar Retention、CAC Payback
省略：Asset Turnover、在庫指標

**製造/産業：**
必須：EBITDA Margin、Asset Turnover、CapEx/Revenue
任意：ROA、在庫回転率、Backlog
省略：Rule of 40、SaaS指標

**金融サービス：**
必須：ROE、ROA、Efficiency Ratio、P/E
任意：Net Interest Margin、貸倒引当金
省略：Gross Margin、EBITDA（銀行には意味をなさない）

**小売/Eコマース：**
必須：Revenue Growth、Gross Margin、在庫回転率
任意：Same-Store Sales、Customer Acquisition Cost
省略：R&Dやハードな設備投資指標

### 「5-10ルール」

**オペレーティング指標5つ** — Revenue、Growth、マージン/効率性指標2〜3
**バリュエーション指標5つ** — Market Cap、EV、マルチプル3つ
**= 合計10列** — ストーリーを伝えるのに十分で、テーマを見失わない量

15指標を超える場合は、おそらくノイズを含んでいる。徹底的に削ること。

## Section 6：ベストプラクティスとクオリティチェック

### 開始前に
1. **ピアグループを定義する** — 本当に比較可能な企業（類似のビジネスモデル、規模、地域）でなければならない
2. **適切な期間を選ぶ** — LTMは季節性を平滑化し、四半期はトレンドを示す
3. **単位を統一する** — 百万 vs 十億の決定はすべてに影響する
4. **データソースをマッピングする** — 各数値がどこから来ているか把握する

### 構築中に
1. **生データをすべて先に入力する** — フォーミュラを書く前にブルーテキストを完成させる
2. **すべてのハードコードのインプットにセルコメントを追加する** — セル右クリック → コメント挿入 → ソースまたは前提を文書化する

   **データとして取得した値には出典を明記する：**
   - 例："Bloomberg Terminal - MSFT Equity DES, accessed 2024-10-02"
   - 例："Q4 2024 10-K filing, page 42, line item 'Total Revenue'"
   - 例："FactSet consensus estimate as of 2024-10-02"
   - **可能な場合はハイパーリンクを含める**：セル右クリック → リンク → SEC filingやデータソースのURLを貼り付ける

   **前提として置いた値には根拠を説明する：**
   - 例："ピアの中央値に基づいてEBITDAマージン15%を仮定、会社は開示していない"
   - 例："Q3貸借対照表からの純負債5,000万ドルを加算してEnterprise Valueを推算（Q4未公表）"
   - 例:"ストリート・コンセンサスEPS $3.45（12名のアナリスト推定の平均）に基づくForward P/E"

   **重要な理由**：監査証跡、データ検証、前提の透明性、および将来の更新を可能にする
3. **フォーミュラを行ごとに構築する** — 次に進む前に各計算をテストする
4. **ヘッダーには絶対参照を使う** — $C$6 でヘッダー行をロックする
5. **フォーマットを統一する** — パーセンテージはパーセンテージとして、小数点では表示しない
6. **条件付き書式を追加する** — 外れ値を自動的にハイライトする

### サニティチェック
- **マージンテスト**：Gross margin > EBITDA margin > Net margin（定義上常に成立する）
- **マルチプルの合理性**：
  - EV/Revenue：通常0.5〜20x（業界によって大きく異なる）
  - EV/EBITDA：通常8〜25x（業界横断でほぼ一定）
  - P/E：通常10〜50x（成長率に依存）
- **成長率とマルチプルの相関**：高い成長率は通常高いマルチプルを意味する
- **規模と効率性のトレードオフ**：大企業は規模の経済によりマージンが高い傾向がある

### よくあるミス
❌ Market Cap と Enterprise Value をフォーミュラ内で混在させる
❌ 分子と分母に異なる期間を使う（LTM vs 四半期）
❌ セル参照の代わりにフォーミュラに数値をハードコードする
❌ **ソースを引用せず、または前提の説明なしにハードコードのインプットをセルコメントなしで使用する**
❌ SEC filingsやデータソースへのハイパーリンクを省略する（利用可能な場合）
❌ 明確な目的なしに過剰な指標を含める
❌ 比較不可能な企業（異なるビジネスモデル）を含める
❌ 開示なしに陳腐化したデータを使用する
❌ パーセンテージの平均を誤って計算する（中央値を使うべき）

## Section 6（続）：高度な機能

### 動的ヘッダー
計算を表す列には明確な単位ラベルを使用する：
```
Revenue Growth (YoY) % | EBITDA Margin | FCF Margin | Rule of 40
```

### 四分位分析の利点
平均・中央値だけでなく、四分位数は分布を示す：
- **75thパーセンタイル** = 「プレミアム」企業の取引水準
- **中央値** = 典型的な市場バリュエーション
- **25thパーセンタイル** = 「ディスカウント」ゾーン

これにより「対象会社はピアと比べて割高か割安か？」への回答が可能になる。

### 業界別の修正

**ソフトウェア/SaaS：**
- 追加：ARR、Net Dollar Retention、CAC Payback Period
- 強調：Rule of 40、FCFマージン、Gross margin >70%

**ヘルスケア：**
- 追加：R&D/Revenue、パイプライン価値、規制状況
- 強調：EBITDAマージン、成長率、償還リスク

**産業：**
- 追加：Backlog、受注残トレンド、地域別ミックス
- 強調：ROIC、Asset Turnover、景気循環調整

**消費財：**
- 追加：Same-store sales、Customer Acquisition Cost、ブランド価値
- 強調：Revenue成長率、Gross Margin、在庫回転率

## Section 7：ワークフローと実践的なヒント

### ステップバイステップのプロセス
1. **構造設定**（30分）
   - すべてのヘッダーを作成する
   - セルをフォーマットする（インプットはブルー、フォーミュラはブラック）
   - 単位と日付参照を固定する

2. **データ収集**（60〜90分）
   - 一次ソースから取得する（利用可能な場合はS&P Kensho MCP、FactSet MCP、Daloopa MCP；なければBloomberg、SEC）
   - 生の数値をすべてブルーで入力する
   - ソースを注記セクションに文書化する

3. **フォーミュラ構築**（30分）
   - 単純な比率（マージン）から始める
   - マルチプル（EV/Revenue）に進む
   - クロスチェックを追加する（マージンは合理的か？）

4. **統計の追加**（15分）
   - すべての列についてフォーミュラ構造をコピーする
   - 範囲が正確か確認する（B7:B9であってB7:B10ではないか）
   - 四分位数ロジックを確認する

5. **クオリティコントロール**（30分）
   - サニティチェックを実行する
   - フォーミュラ参照を確認する
   - #DIV/0! や #REF! エラーを確認する
   - 既知のベンチマークと比較する

6. **文書化**（15分）
   - 注記セクションを完成させる
   - データソースを追加する
   - 方法論を定義する
   - 分析日付をスタンプする

### プロのヒント
- **テンプレートを保存する**：一度作れば永続的に再利用できる
- **外れ値に色を付ける**：2標準偏差超の値に条件付き書式を適用する
- **ソースファイルにリンクする**：BloombergのスクリーンショットやSEC filingsにハイパーリンクを貼る
- **バージョン管理する**："Comps_v1_2024-12-15" のように日付を明記して保存する
- **協働レビュー**：自分のフォーミュラを他者にチェックしてもらう

## Section 10：レッドフラグと警告サイン

### データ品質の問題
🚩 期間の不統一（四半期と年次が混在）
🚩 説明のない欠損データ
🚩 データソース間の重大な差異（10%超の乖離）

### バリュエーションのレッドフラグ
🚩 EBITDAがマイナスの企業にEBITDAマルチプルを使用している（代わりにRevenueマルチプルを使用する）
🚩 ハイパーグロースストーリーなしにP/E比率が100x超
🚩 業界にそぐわないマージン

### 比較可能性の問題
🚩 決算期末が異なる（タイミングの問題が発生する）
🚩 純粋プレイとコングロマリットを混在させる
🚩 「Comps」としてラベリングされているが実質的にビジネスモデルが大きく異なる

**疑わしい場合は除外する。** 3社の完璧なCompsは、6社の疑わしいCompsより優れている。

## Section 11：フォーミュラ参照ガイド

### 必須のExcelフォーミュラ
```excel
// 統計関数
=AVERAGE(range)          // 単純平均
=MEDIAN(range)           // 中央値
=QUARTILE(range, 1)      // 25thパーセンタイル
=QUARTILE(range, 3)      // 75thパーセンタイル
=MAX(range)              // 最大値
=MIN(range)              // 最小値
=STDEV.P(range)          // 標準偏差

// 財務計算
=B7/C7                   // 単純比率（マージン）
=SUM(B7:B9)/3            // 複数企業の平均
=IF(B7>0, C7/B7, "N/A")  // 条件付き計算
=IFERROR(C7/D7, 0)       // ゼロ除算の処理

// 他シートへの参照
='Sheet1'!B7             // 別シートへの参照
=VLOOKUP(A7, Table1, 2)  // データテーブルからの参照
=INDEX(MATCH())          // 高度な参照

// フォーマット
=TEXT(B7, "0.0%")        // パーセンテージとしてフォーマット
=TEXT(C7, "#,##0")       // 千単位区切り
```

### よく使う比率のフォーミュラ
```excel
Gross Margin = Gross Profit / Revenue
EBITDA Margin = EBITDA / Revenue
FCF Margin = Free Cash Flow / Revenue
FCF Conversion = FCF / Operating Cash Flow
ROE = Net Income / Shareholders' Equity
ROA = Net Income / Total Assets
Asset Turnover = Revenue / Total Assets
Debt/Equity = Total Debt / Shareholders' Equity
```

## 主要原則のまとめ

1. **構造がインサイトを生む** — 正しいヘッダーが正しい思考を強制する
2. **少ない方が優れている** — 重要な5〜10指標は、重要でない20指標に勝る
3. **問いに合った指標を選ぶ** — バリュエーション分析と効率性分析は同じではない
4. **統計はパターンを示す** — 中央値と四分位数は平均より多くを明らかにする
5. **透明性が複雑さに勝る** — 誰でも理解できるシンプルなフォーミュラ
6. **比較可能性が王道** — 無理にCompsに入れるより除外した方が良い
7. **選択を文書化する** — どの指標を選んだか、なぜかを注記セクションに説明する

## アウトプットチェックリスト

Comps分析を納品する前に確認する：
- [ ] すべての企業が本当に比較可能である
- [ ] データは一貫した期間のものである
- [ ] 単位が明確にラベリングされている（百万/十億）
- [ ] フォーミュラはハードコードの値でなくセルを参照している
- [ ] **すべてのハードコードのインプットセルに、①正確なデータソースと引用、または②明確な前提と説明のいずれかを含むコメントが付いている**
- [ ] **該当する箇所にハイパーリンクが追加されている**（SEC EDGAR filings、Bloombergページ、調査レポート）
- [ ] 統計に少なくとも5つの指標が含まれている（Max、75th、Med、25th、Min）
- [ ] 注記セクションにソースと方法論が文書化されている
- [ ] ビジュアルフォーマットが規約に従っている（ブルー = インプット、ブラック = フォーミュラ）
- [ ] サニティチェックが通る（マージンが論理的、マルチプルが合理的）
- [ ] 日付スタンプが最新である（"As of [日付]"）
- [ ] フォーミュラ監査でエラーなし（#DIV/0!、#REF!、#N/A）
